# صلة (Silah) — نظام إدارة الأنساب وحساب صلات القرابة

تطبيق كامل لإدارة شبكة قرابة عائلية (Kinship Graph) وحساب صلة القرابة بين أي شخصين
تلقائيًا، مبني كرسم بياني (Graph) وليس كشجرة بسيطة — يدعم الزيجات المتعددة، الطلاق،
الوفاة، الأشخاص مجهولي الوالدين، التبني، والمصاهرة، مع محرك قرابة عام (BFS + أقرب سلف
مشترك) وليس سلسلة شروط ثابتة.

## لماذا هذه التقنية؟

- **Node.js فقط، بدون أي حزمة خارجية (Zero external dependencies).** قاعدة البيانات
  SQLite مضمّنة في Node.js نفسه (`node:sqlite`)، والخادم HTTP، والتحقق من كلمات المرور
  (`scrypt`)، والاختبارات (`node:test`) — كلها من مكتبة Node القياسية. هذا يعني: لا
  `npm install` قد يفشل، لا اعتماد على خدمة سحابية، لا تكلفة، ونشر بسيط لأي بيئة تشغّل
  Node.js.
- **الواجهة**: HTML/CSS/JavaScript عادي (بدون خطوة Build)، متجاوبة (Mobile First)، تدعم
  العربية RTL والإنجليزية LTR عبر نظام ترجمة (i18n) كامل — لا نصوص مكتوبة مباشرة داخل
  المكوّنات.
- **بدون أي مفتاح API أو خدمة مدفوعة.**

## المتطلبات

- **Node.js إصدار 22.5 أو أحدث** (يحتاج `node:sqlite` المدمجة). تحقق بالأمر:
  ```
  node -v
  ```
  إن لم يكن مثبتًا لديك، حمّله من https://nodejs.org (الإصدار LTS الأحدث).

لا تحتاج أي شيء آخر: لا قاعدة بيانات منفصلة، لا Docker (اختياري فقط)، لا حساب سحابي.

## التشغيل المحلي (3 أوامر)

```bash
cd silah
node seed/seed.js        # (اختياري) يُنشئ بيانات تجريبية وحساب دخول جاهز للتجربة
node server/app.js       # يشغّل الخادم على http://localhost:3000
```

افتح المتصفح على `http://localhost:3000`. إن استخدمت `seed.js` يمكنك الدخول مباشرة بـ:

- البريد: `demo@silah.app`
- كلمة المرور: `Demo@12345`

أو أنشئ حسابًا جديدًا من صفحة "إنشاء حساب".

### أوامر أخرى مفيدة

```bash
npm run dev         # تشغيل مع إعادة التحميل التلقائي عند تعديل الكود
npm run seed:reset  # حذف قاعدة البيانات الحالية والبدء من جديد ببيانات تجريبية نظيفة
npm test            # تشغيل جميع الاختبارات الآلية (محرك القرابة + API)
```

## هيكل المشروع

```
silah/

    app.js              نقطة تشغيل الخادم HTTP وربط كل المسارات
    db.js                مخطط قاعدة البيانات (SQLite) بالكامل
    lib/
      kinship-engine.js  محرك حساب القرابة (BFS + أقرب سلف مشترك) — القلب الحقيقي للنظام
      auth.js             تسجيل الدخول، تشفير كلمات المرور، الجلسات
      validate.js          التحقق من صحة المدخلات
      csv.js                قراءة/كتابة CSV بدون مكتبات خارجية
      http-kit.js            أدوات خادم HTTP (توجيه، JSON، ملفات ثابتة)
      audit.js                سجل العمليات (Audit Log)
    routes/                كل نقاط الـ API (أشخاص، علاقات، زيجات، قرابة، شجرة، لوحة تحكم، استيراد/تصدير، دخول)
  public/                  الواجهة الأمامية (HTML/CSS/JS عادي، بدون Build)
  tests/                    اختبارات آلية (node:test) — محرك القرابة + تكامل API
  seed/seed.js             بيانات تجريبية شاملة (زيجات متعددة، طلاق، تبني، مصاهرة...)
  data/                      قاعدة البيانات (تُنشأ تلقائيًا؛ ملف silah.db)
```

## محرك القرابة (Kinship Engine) — كيف يعمل

الملف: `server/lib/kinship-engine.js`

1. يبني رسمًا بيانيًا (Graph) في الذاكرة من جدولي `parent_child` و `marriages` الخاصين
   بالمستخدم الحالي فقط.
2. يبحث بخوارزمية BFS صاعدة عن جميع أسلاف كل شخص من الاثنين، مع الاحتفاظ بالمسار الكامل
   (وليس فقط المسافة) لكل سلف — هذا يسمح بمعرفة جنس كل قريب على المسار ونوع العلاقة
   (بيولوجي/تبني) في كل خطوة.
3. يجد تقاطع الأسلاف (Common Ancestors)، ويختار الأقرب (أقل مجموع مسافة) — وهذا هو
   أساس خوارزمية "أقرب سلف مشترك" (Lowest Common Ancestor).
4. يشتق نوع القرابة واسمها العربي من مسافتي الشخصين إلى السلف المشترك، لا من حالات
   مكتوبة يدويًا لكل قرابة — أي أن النظام **عام (generic)** ويعمل لأي درجة قرابة
   (ابن ابن العم، بنت بنت الخال...) دون تعديل الكود.
5. المصاهرة (Marriage/Affinity) تُحسب بشكل منفصل تمامًا عن قرابة الدم (Blood)، وتُعرض
   كعلاقة إضافية عند وجودها.
6. إن وُجد أكثر من سلف مشترك بنفس الدرجة (كالجد والجدة معًا)، يُدمَجان في نتيجة واحدة؛
   أما إن أدت المسارات إلى **نوعين مختلفين فعليًا** من القرابة (قرابة دم + مصاهرة معًا
   مثلًا)، تُعرض كل العلاقات صراحة مع رسالة "توجد أكثر من صلة قرابة".
7. لا تخمين: إن لم توجد بيانات كافية، يُعرض "لم يتم العثور على صلة قرابة معروفة ضمن
   البيانات الحالية" بدل تخمين نتيجة.
8. حماية من الدوران اللانهائي عبر حد أقصى للأجيال (30) وتتبّع المسار الحالي أثناء البحث.

الاختبارات الآلية في `tests/kinship-engine.test.js` تغطي: الأب/الأم، الجد/الحفيد،
حفيد الحفيد، الإخوة الأشقاء، نصف الإخوة، العم/العمة/الخال/الخالة، أبناء العم/الخال،
المصاهرة (زوج الأخت)، التبني، منع الدورات، الأشخاص مجهولي الوالدين، عدم وجود صلة،
والأداء مع آلاف الأشخاص.

## الأمان

- **عزل بيانات كامل بين المستخدمين على مستوى طبقة البيانات**: كل استعلام SQL في كل
  مسار API يتضمن `owner_id = ?` (معرّف المستخدم المسجّل دخوله) — لا يوجد أي مسار
  يعيد بيانات مستخدم آخر، وهذا مغطى باختبار آلي مخصص (`tests/api.test.js`) يتحقق أن
  مستخدمًا لا يستطيع رؤية شخص أنشأه مستخدم آخر حتى عبر تخمين الـ ID مباشرة (IDOR).
- كلمات المرور: `scrypt` (دالة اشتقاق مفتاح مقاومة لهجمات القوة الغاشمة) + ملح عشوائي
  فريد لكل مستخدم — لا تُخزَّن كلمات المرور نصًا صريحًا أبدًا.
- الجلسات: رموز عشوائية 256-بت، تُخزَّن كـ hash فقط في القاعدة، صلاحية 30 يومًا.
- حماية من SQL Injection: كل استعلام يستخدم Prepared Statements حصرًا (بدون أي دمج
  نصي للمدخلات في الاستعلام).
- حماية من XSS: كل نص من المستخدم يُعرض عبر `escapeHtml`/`escapeXml` قبل إدراجه في
  DOM أو SVG.
- رؤوس أمان أساسية (X-Content-Type-Options، X-Frame-Options) وتحديد لمعدل الطلبات
  (Rate limiting).
- التحقق من صحة المدخلات على الخادم دائمًا (وليس فقط في الواجهة).

## النسخ الاحتياطي والتصدير

من صفحة "الاستيراد والتصدير" يمكن تصدير كامل بياناتك (JSON يتضمن الأشخاص والعلاقات
والزيجات، أو CSV للأشخاص). ملف قاعدة البيانات نفسه هو أيضًا ملف واحد قابل للنسخ مباشرة:
`data/silah.db` (استخدم أداة نسخ الملفات العادية لعمل نسخة احتياطية كاملة أو نقل
البيانات لخادم آخر).

## النشر (Deployment)

التطبيق عبارة عن عملية Node.js واحدة تخدم API والواجهة الثابتة معًا على منفذ واحد —
ينشر على أي مزوّد يدعم Node.js (VPS عادي، Render، Railway، Fly.io، أو خادم شخصي)
دون الحاجة لخدمة قاعدة بيانات منفصلة.

### تشغيل بسيط على خادم (VPS)

```bash
node server/app.js
# أو مع إبقائه يعمل في الخلفية:
nohup node server/app.js > silah.log 2>&1 &
```

يمكن ضبط المنفذ عبر متغير البيئة `PORT` (افتراضي 3000).

### Docker (اختياري)

ملف `Dockerfile` مرفق. للبناء والتشغيل:
```bash
docker build -t silah .
docker run -p 3000:3000 -v silah_data:/app/data silah
```

### الإبقاء على الخدمة تعمل تلقائيًا (systemd)

راجع `docs/deployment.md` لمثال كامل على ملف خدمة systemd لإعادة التشغيل التلقائي عند
إعادة تشغيل الخادم أو حدوث عطل.

## الاختبار

```bash
npm test
```

يشغّل جميع الاختبارات في `tests/` باستخدام مُشغّل الاختبارات المدمج في Node.js

## حدود هذا الإصدار (بصراحة تامة)

هذا إصدار أول متكامل وقابل للتشغيل والنشر فعليًا، وليس نموذجًا أوليًا. مع ذلك، الأمانة
التقنية تقتضي توضيح ما لم يُستكمل بعد ليكون أول استخدام لك أوضح:

- **تصدير/استيراد GEDCOM**: لم يُنفَّذ في هذا الإصدار (البنية تدعم إضافته لاحقًا دون
  تعديل جوهري في محرك القرابة أو قاعدة البيانات).
- **مشاركة الشجرة العائلية بين المستخدمين (Owner/Editor/Viewer)**: جدول `family_shares`
  جاهز في قاعدة البيانات، لكن واجهة الاستخدام ومنطق الصلاحيات المرتبط به غير مُفعّلين
  بعد — كل بيانات المستخدم خاصة به فقط حاليًا.
  - عرض شجرة "مجموعة أشخاص" في صفحة العائلات مبسّط حاليًا (يعرض شجرة الشخص الأول
    المحدد مع بقية المجموعة كسياق) بدل تخطيط بصري موحّد لكل الشبكة — الحساب والبيانات
    الخلفية (`/api/tree/group`) صحيحة وتعيد كل الأسلاف والفروع الصحيحة، لكن رسم SVG
    موحّد لعدة جذور هو تحسين واجهة يستحق جولة تالية.
  - لم يُختبر رسميًا حتى مقياس 100,000 شخص (الاختبارات الآلية تغطي آلاف السجلات وتؤكد
    أن البنية — الفهارس، BFS محدود بعدد الأجيال لا بحجم القاعدة كاملة — سليمة نظريًا
    لهذا الحجم، لكن الاختبار الفعلي بحمل واقعي يحتاج بيئة تشغيل حقيقية).

كل ما سبق موثّق هنا بدل التسويق له كمكتمل، وأي منها قابل للتنفيذ في جولة عمل تالية دون
إعادة هيكلة الأساس (قاعدة البيانات ومحرك القرابة ثابتان ولن يحتاجا تعديلًا جوهريًا).
